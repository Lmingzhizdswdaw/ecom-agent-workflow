# 链路 ③ 广告计划搭建

> 目标：输入「一个商品 + 两张表」，输出「4 条已就绪待提交的广告计划」，全程零手工填字段。
> 关键词：声明式配置、约束倒推、状态复位、先删后填、不动作区、幂等防重

---

## 一、链路总览

```
① 引用规则模版 ──▶ ② 勾选广告户 ──▶ ③ 广告基本信息
                                          │
        ⑥ 生成并提交 ◀── ⑤ 创意素材 ◀── ④ 创意基本信息
```

**输入是两张表**：

| 表 | 内容 | 作用 |
|---|---|---|
| **商品信息表** | 商品全名、商品ID、商品出价、商品落地页、素材路径 | 这个品"是什么" |
| **账户映射表** | 商品全名 + 2 个广告户 | 这个品"投到哪" |

> **设计要点：数据与映射分离。** 两张表以**商品全名**为共同主键关联。换投放策略时只改账户映射表，商品数据完全不用动。

---

## 二、数量约束的推导链

```
业务要求：一个品 4 条广告
        ÷ 单个广告户上限 2 条
        ───────────────────
        = 需要 2 个广告户
        × 每户 2 条
        = 4 条
```

**这是整条链路的结构性约束**：4 条不是任意定的，是由"单户上限 2 条"这个硬限制倒推出来的。**数量一变，账户选择逻辑要跟着变。**

**连带结论**：既然一个品要建 4 条**主体完全相同**的计划，广告名必须防重 → 所以命名模板里带 `[随机ID]`。

> **同一个数量约束，在两个地方独立产生了设计影响**（账户数、命名防重）。这类"约束的连锁反应"是设计文档最该记录的东西。

---

## 三、流程与关键机制

### 步骤 1 · 引用规则模版

`广告平台 → 批量搭建广告 → 引用规则模版 → 选第 1 个模版 → 确定`

**规则模版是执行者自己配置的**，不是平台自带：因为"里面很多默认值每次填法都一样，设成模版比较方便"。

> 这是**由执行者反向定义工具配置**：先识别出「每次都要填、且每次填法都一样」的字段，抽成可复用模版，运行时一句"引用"代替重复劳动。
> 专业术语对应：**Declarative Rules Engine（声明式规则引擎）**——业务规则以声明式配置存在，而非散落在每次操作的硬编码里。

### 步骤 2 · 勾选广告户

`媒体账号 → 更改 → 清空 → 粘贴 2 个户 → 搜索 → 全选 → 确定`

**关键机制：先清空，再勾选 = 幂等前置动作。**
不先清空，上一次的账户会残留 → 张冠李戴，批量错一批计划。

### 步骤 3 · 广告基本信息（只改 3 处）

#### 3-1 设置商品 ⚠️ 状态重置陷阱

`设置商品 → 账号分别设置 → 商品库下拉选店铺 → 搜商品全名 → 户1选品1 → 户2选品2`

**户与品严格按顺序一一对应。** 而这里有一个**静默状态重置**：

> **切换账户时，商品库选择会被清空，且没有任何提示。**

**处置**：选第 2 个户之前，**必须重新选一次商品库**，否则第 2 个户会带着空商品库提交。

> 人工操作靠肌肉记忆躲过；**自动化脚本若不知道这件事，就会批量生成一批错计划。**
> 这在专业上叫**隐式状态管理**：跨上下文切换后必须重新校验关键字段。

#### 3-2 设置优化目标

**只改「多少元」这一框，填商品信息表里的出价——不四舍五入，直接截断取整。**（`12.7 → 12`）

> **截断是保守取值**：宁可出价略低于目标，也不向上突破成本线。**这是成本可控性决策，不是随手定的规则。**

#### 3-3 广告名称（结构化命名）

```
{组名}+{操作人}+{商品缩写}+{商品ID}+{平台码}+{店铺}[下发时间][随机ID]
```

| 片段 | 来源 |
|---|---|
| 组名 / 操作人 / 平台码 / 店铺 | 固定常量 |
| **商品缩写** | **模型理解商品全名后压缩为 2–5 字** |
| 商品ID、出价 | 商品信息表 |
| 下发时间、随机ID | 系统生成 |

**命名承载三件事**：可追溯（谁、哪个品、哪个店、什么时候）、防重（随机ID）、人机可读。

### 步骤 4 · 创意基本信息（只改 1 处）

- **定向包 → 不动，保持默认** 🚫
- 跳转类型选落地页 → **先删除原有路径，再粘贴商品落地页链接**

**关键机制：先删后填。** 表单输入框不会自动覆盖，不清空就写入会导致新旧路径拼接 → 跳转直接失效。**这是自动化填表的经典坑。**

### 步骤 5 · 创意素材

`删光已有素材 → 加号添加 → 文件夹目录 → 搜商品ID → 点"全部" → 确定`

- **素材以商品 ID 归档** —— 素材库索引键与链路①、②统一，**三条链路在这一步正式汇合**
- **上限 15 条，超出直接丢弃**（不分批、不筛选：超出部分无处安放，复杂逻辑不产生价值）
- 同样是**先删后加**

### 步骤 6 · 生成并提交

`生成广告计划 → 开始提交` 🛑 **不可逆的花钱动作，必须人工确认后执行**

## 四、设计要素汇总

| # | 要素 | 专业命名 |
|---|---|---|
| 1 | 执行者自建规则模版 | Declarative Rules Engine |
| 2 | 4 条 → 2 户的约束倒推 | 需求 → 约束 → 推导 |
| 3 | 两张表以商品全名关联 | 关注点分离 / 数据与规则分离 |
| 4 | 先清空再勾选 | 幂等前置动作 |
| 5 | 切换账户后必须重设商品库 | 隐式状态管理（**全链路最硬的坑**） |
| 6 | 落地页、素材先删后填 | 表单覆盖陷阱 |
| 7 | 定向包 / 动态商品广告信息保持默认 | 不动作区 |
| 8 | 命名带随机ID | 幂等防重 |
| 9 | 出价截断取整 | 保守取值 |
| 10 | 素材超 15 条直接丢弃 | 边界简化 |
| 11 | 商品缩写压缩为 2–5 字 | LLM 语义 + 长度约束（**全链路仅 1 处需"理解"**） |
| 12 | 登录人工、Agent 只操作已登录会话 | 认证边界 |
| 13 | 提交/出价/预算必须人工确认 | 分级自动化 |

---

## 五、异常与边界

| 场景 | 处置 |
|---|---|
| 素材超过 15 条 | 截断丢弃 |
| 搜商品ID 无素材 | 回链路①（素材采集）处理 |
| 商品库下拉无目标店铺 | 回报（未遇） |
| 提交后被拒审 | 回报（未遇） |
| 账户登录态失效 | 人工重新登录 |

---

## 六、效率

| 指标 | 数值 |
|---|---|
| 单次规模 | **一次 1 个品** |
| 产出 | **4 条广告计划**（2 户 × 2 条） |
| 人工耗时 | **约 3–5 分钟/品** |
| 需要"理解"的环节 | 1 处（商品缩写） |
