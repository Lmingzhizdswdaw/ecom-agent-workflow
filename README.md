# ecom-agent-workflow

> 把跨境电商投流业务中三条高重复度人工链路，设计成可被 Agent 端到端执行的自动化工作流。
> **选品与素材采集 → 铺货上架 → 广告计划搭建**，横跨 5 个业务系统。

**作者**：刘明智 ｜ **时间**：2026.07 – 2026.09 ｜ **形式**：独立设计流程规则，协同 AI 编码实现

---

## 一句话简介

业务侧是「货源系统分销 + 短视频平台投流」的无货源模式；技术侧是把这条链路上**重复、规则明确、但跨系统手工搬运**的部分，交给 Agent 执行——**人只做两件事：登录，和拍板。**

---

## 为什么值得做

投流业务里，一个商品的完整上线流程是这样的：

```
选品 → 找素材 → 铺货上架 → 建广告计划
  │        │          │            │
  │        │          │            └─ 客户端里点 6 步、填 20+ 个字段，一个品出 4 条广告
  │        │          └─ 4 个后台之间搬 ID、填落地页、传主图，24 个步骤
  │        └─ 平台搜索、逐条比对、下载转码、按品归档
  └─ 在自有货盘里选款
```

**每一步单看都不难，加起来一个品 30–60 分钟，而且全是"照规则执行"，不需要人的判断力。**
真正的判断力只用在 3 个地方（见下方"规则与判定标准"），其余全部可以结构化。

## 功能特性

| # | 链路 | 输入 | 输出 | 跨系统 |
|---|---|---|---|---|
| 1 | **选品与素材采集** | 品名 / 选品关键词 | 按品归档的对版素材夹 + 逐条判定留痕 | 货源系统、短视频平台 |
| 2 | **铺货上架** | 商品全名 | 广告平台商品库中已提交的商品 | 货源系统 → 电商平台 → 落地页中转系统 → 广告商品库 |
| 3 | **广告计划搭建** | 商品信息表 + 账户映射表 | 4 条待提交广告计划（含命名、出价、落地页、素材） | 投放客户端（CDP 接管） |

**共同设计**：
- **统一主键贯穿全链**：`商品全名` 串联三条链路，`商品ID` 串联平台侧与素材库
- **数据与规则分离**：业务参数集中在 `data/rules.yaml`，改规则不改代码
- **分级自动化**：只读自主执行 / 可逆操作汇报 / 花钱动作必须人工确认
- **认证边界**：Agent 只操作已登录会话，不接触账号凭证与验证码

## 规则与判定标准（本项目最核心的部分）

工具会更新，界面会改版，**真正沉淀下来的是这些判定规则**。

### 1. 三个阈值

| 阈值 | 值 | 为什么是这个值 |
|---|---|---|
| 素材与基准图相似度 | **≥ 90%** | 低于此值买家会看出货不对版。判定粒度是**款型级**（形状/结构/材质/大小/人群不同即不算同一产品），**颜色图案差异不计** |
| 可用素材条数 | **≥ 5 条** | 低于 5 条投不出量；**不硬凑、不为凑数降标准，直接弃品** |
| 素材单次取用条数 | **≤ 15 条** | 系统上限。超出部分无处安放 → **直接截断丢弃**，不做分批也不做筛选 |

### 2. 数量约束的推导链

```
业务要求：一个品 4 条广告
        ÷ 单个广告户上限 2 条
        ───────────────────
        = 需要 2 个广告户
```

> 这不是习惯，是**约束倒推**：数量变化时整条账户选择逻辑都要跟着变。同理，广告名里的 `[随机ID]` 也是被"4 条同名计划"倒逼出来的防重复设计。

### 3. 兜底规则（宁可填默认值，也不让流程中断）

| 场景 | 兜底动作 |
|---|---|
| 商品属性无对应项 | **直接选第一个** |
| 品牌字段 | 固定值「无」 |
| 关键词下无已合作商品 | ⛔ **例外：报警停止，不降级放宽**（选品是硬边界） |

### 4. 不动作区（明确划出禁区）

- 商品库里的「动态商品广告信息」— 保持默认，禁改
- 创意信息里的「定向包」— 保持默认，禁改
- 名称、店铺、业务单元等固定值 — 禁改

### 5. 全链路只有 2 处需要"理解"

| 环节 | 需要模型做什么 |
|---|---|
| 铺货 · 类目与商品属性 | 按商品全名/图片理解归类 |
| 建计划 · 商品缩写 | 把商品全名压缩成 2–5 字 |

其余 40+ 个动作全是确定性规则。**"判断哪里可以松、哪里必须严"本身就是核心设计工作**——例如商品库是内部中间层（终端用户看不到），类目选错不阻断流程，所以允许全自动且宽松；而落地页链接直接影响投放跳转，必须严格按常量执行。

### 6. 分级自动化与认证边界

| 级别 | 范围 | 策略 |
|---|---|---|
| 只读 | 查报表、看计划状态 | Agent 自主执行 |
| 可逆 | 建草稿、填表、传素材 | 执行后汇报 |
| **不可逆 / 花钱** | 提交计划、出价、改预算、开关投放 | ⛔ **逐次人工确认** |
| 认证 | 平台登录、验证码 | ⛔ **必须人工**，Agent 不接触凭证 |

## 性能指标

| 链路 | 人工耗时 | 产出 |
|---|---|---|
| ① 选品 | 待补测 | 选品基准 |
| ② 素材采集 + 视觉核对 | **约 15–25 分钟/单** | 对版素材夹 |
| ③ 铺货上架（4 系统 24 步） | **约 10 分钟/品** | 商品库就绪商品 |
| ④ 广告计划搭建（6 步） | **约 3–5 分钟/品** | 4 条广告计划 |

| 质量指标 | 数值 |
|---|---|
| 素材采集单量命中率 | 样本：10 条到位，另有 4 条测评/避坑内容被规则拦下 |
| 视觉核对复核一致性 | 与人工复查结果**完全一致**（泡脚桶 通过7/剔除3；护腰带 通过9/剔除1） |
